# 数值自洽校验

`NUMERIC_CHECK_ENABLED` 默认关闭。开启后，Critic 会在既有 Evidence 与
`finance_metric_normalization.json` 归一边界内做确定性算术校验，不访问外部数据源。

## 支持的关系

- 同比/环比增长率：用当前期与比较期绝对值计算。
- 占比：用分子除以分母计算。
- 合计：用两个或更多分项之和核对声称的总值。
- 单位换算：支持亿、万、元以及百分比、小数之间的机械换算。

关系字段使用明确的确定性命名：`指标同比增长率`、`分子占分母占比` 和
`总计=分项A+分项B`。这不是自然语言推断器。

## 口径与容差

参与项先复用金融指标 alias 表归一；实体、报告期和 scope 必须匹配。scope 不一致时
不做算术核验，而是产生既有 `numeric_conflict` issue 并明确记录
`skip_scope_conflict` 决策。

默认相对容差为 `0.01`（1%），绝对容差为 `0.01`。1% 用于吸收财报展示值按万/亿
或百分点四舍五入造成的尾差；绝对 0.01 则覆盖接近零或只保留两位小数的展示值。
两个容差均可通过环境变量配置，并随每次 `AgentDecision` 记录。超出容差时产生
`numeric_inconsistency`，其中必须包含声称值、计算值、关系式和参与计算的
evidence IDs，并进入既有 retry queue。

这些 fixture 测试证明规则按定义执行，不证明规则覆盖真实研究中的全部表达方式；
规则覆盖度与真实质量影响待 019 验证。
