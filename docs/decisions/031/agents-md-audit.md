# 031 AGENTS.md 与任务卡事故审计

## 结论

021–030 的六类已知停摆中，五类直接来自任务卡写法；唯一被执行报告明确归因给
`AGENTS.md`、且只挡住工作的事故，是“只执行提示词明确事项”与“卡和仓库现实冲突
即停止”叠加。028 因此没有修复缺失的 disclosure 路由，030 才补完三处断点。
后文任务卡表列出七种应停用写法；末两项是对已知事故机制的补充描述，不另计为独立
停摆类别。

这不意味着应删除安全规则。密钥、外部写、付费预登记、测试真实性、冻结评测语料、
provider 边界和全量验证都防住了真实损害。应修的是相互冲突的停止规则、把预登记误当
二次审批的措辞，以及评测语料与 characterization snapshot 混用“冻结”的边界。

本审计只依据本仓库事故记录；未用其他项目模板替代自身证据。按任务卡硬边界，本轮
只提出建议，未修改 `AGENTS.md`。

- 022、024、029 缺少对应 `docs/decisions/<round>/` 记录。

## AGENTS.md 修订建议（待 PM 批准）

### 1. 合并“范围、仓库现实与停止”四条冲突规则

建议改为：

> 执行范围由任务目标、验收和硬边界共同限定；任务列表是建议路径。任务卡中的
> 代码事实与仓库不符时，以仓库现实修正描述，并继续最小的 in-scope 修复。
> 只有触及明确硬边界、不可逆外部动作、未授权费用或重大产品选择时，才停止该项
> 请示。断言、契约或 gate 失败只阻塞依赖阶段，独立阶段继续。

理由：保留 scope 与安全，消除 028 那种“为了遵守仓库现实，反而不能修仓库现实”的
自相矛盾。

### 2. 把付费授权与预登记分开

建议改为：

> 本轮已明确授权 provider、次数和预算时，preregistration 是执行前置，不是第二次
> 审批；没有本轮成本授权时不得付费调用。真实 trajectory 录制遵循同一预算，不另设
> 隐式审批门。

### 3. 区分两类“冻结”

建议改为：

> `data/golden_set/*` 等评测语料 immutable/versioned；`tests/golden_output/*`
> 是 characterization snapshot，可在逐 hunk 归因、专门提交及全量门禁后更新。
> 禁止仅为消除测试失败而更新任一类资产。

### 4. 加入无条件本地全门禁

> 任意代码、测试或配置变化后，在报告/交付前必须跑完整门禁；push/merge 授权只控制
> 外部写，与本地验证无关。

### 5. 固化“新实验”定义

> 代码改变后的运行是新实验，必须验证；禁止的是相同代码反复运行后挑选最好结果。
> 所有成功、失败和熔断运行均记录。

### 6. 修正 AGENTS 自身事实漂移

- 删除手抄默认值，改由校验脚本生成或至少在 CI 比对 `Settings`。
- 把 dynamic capability 默认值更新为 true。
- 把技术栈小节的浮动依赖描述更新为实际精确版本，并与 CI 单一事实源核对。
- 把 019 专属支出顺序和成功判据移到历史决策引用，不再作为所有后续任务常驻执行顺序。
