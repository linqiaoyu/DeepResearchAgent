# 019-C 对 019-D 的影响

## 结论

019-D 当前不具备启动付费实验的条件。该结论不修改 019-B 的预登记：`REACHABLE=2 < 4` 与 STOP 继续有效；019-C 又发现三个并列且更早的阻断条件。

## 已证实事实

1. 充分性分数在未饱和输入上会动，但 019-B stub 两轮均处于 `[1,1,1,1,0,1]` 的平台区；tool call 从 5 增至 9 时 Evidence 仍为 6，唯一变化候选是未解决 issue，而该 issue 没有消失。以当前分数作为“增量证据效果”因变量无法归因。
2. `max_iterations=2` 的真实 ReflectionReasoningInterface 输入只有 `2/4` 类非零信号、816 个规范化 JSON 字符。fixture 深度 3 首次达到 `3/4` 类非零，tool call 从 9 增到 14，即 `1.56x`；深度 4 被 no-progress window 截止，没有新增信息。
3. 四个数值观测之间 period 不同且没有增长、占比或合计关系，`checks=0` 是正确行为；完整增长关系能触发 `checks=1`。这不是 019-D 的代码阻断，但说明本题不能用“数值检查次数”作为效果证据。
4. financial/event 能力现已选择并实际执行 `web_fetch`，决策经 AgentDecision、DecisionGate 和预算轨迹记录。
5. APBEC 在冻结阈值下为 0：六题闭合率均为 0，`0/6` 题达到 `2/3`。Q01/Q26 到达公司 PDF 但未读到正文；其余四题没有抓到一手正文。
6. 零网络 11 开关全图可完成，四类产物、引用闭合、DecisionGate 和 NodeContract 均通过。因此软件管道可执行，但实验仪器与一手证据基础不成立。

## 给 PM 的建议

建议按以下决策顺序处理，任何一项都需要更新或重写 019 的预登记后才可付费：

1. 先选择主要因变量：
   - 改为连续的原子口径闭合增量/有效新 Evidence 增量；或
   - 保留充分性分数，但把实验问题缩窄为“候选是否消除指定 Critic issue”。
2. 决定 Reflection 深度：
   - 若仍比较反思候选，建议评审 `max_iterations=3`；
   - 预计 fixture tool call 成本为原设计的 `1.56x`，但本卡不修改参数或预算。
3. 先闭合一手文档链路：
   - 支持公司/法定披露 PDF 正文；
   - 对一手域名或发布主体做确定性 rerank/直连；
   - 使用冻结 APBEC 重新测量，不事后改阈值。
4. 只有当因变量可区分候选、反思输入达到 PM 接受的信息量、且一手闭合达到预先接受的门槛后，再判断 019-D 是否值得付费。

## 不建议的动作

- 不以 C8 “全图跑通”替代实验有效性；
- 不把 Tavily snippet 计作一手正文；
- 不用增加迭代数掩盖因变量平台区；
- 不因 APBEC=0 修改冻结分母或阈值；
- 不把 019-C 结果表述为推翻 019-B STOP；
- 不在没有新预登记的情况下调用任何付费模型。

## 尚未证实

本卡没有证据证明深度 3 会改善真实 LLM 判断、PDF 解析/rerank 会让 APBEC 达标、任何模型会消除 Critic issue，或增加付费预算会改善结果。以上只能作为下一轮可证伪假设，不能作为完成声明。
