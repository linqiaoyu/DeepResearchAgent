# 这套方法测不到什么

## 快照能证明变化，不能自动证明质量

Characterization 快照擅长回答“默认行为是否变了”。它把报告、ReportClaim、
Evidence、Critic 问题、retry queue、Evaluator 结果和节点摘要规范化后逐字比较，
因此可以可靠检出字段、内容、顺序或指标的变化。

它不能仅凭 fixture 质量数字回答“改动是否让研究更好”。只要能力会选择、删除、
合并或重排 Evidence，报告生成和后续评分就可能同时受到 fixture 特有的顺序、
模板和词面匹配规则影响。此时指标仍可重复，却可能只是在测量 harness 的内部耦合，
而不是用户关心的研究质量。这样的数字是伪信号。

## 已观察到的反例

Context packer 修复了同一 URL 下不同摘录被错误合并的问题。修复后，两个固定题面
保留的 Evidence 分别从 5 条增加到 12 条、从 4 条增加到 13 条；deterministic
引用准确率却从 1.000 降到 0.667、从 0.250 降到 0.000。若直接把该数字当作
研究质量，结论会是“保留更多有效摘录反而让引用更差”，这与实际数据流不符。

只读归因复现了相同结果，并用两个对照隔离了机制：

- 只删除重复 Evidence、保持顺序，两个题面的引用准确率均为 1.000。
- 不删除任何 Evidence，只让 Reporter 与 Evaluator 使用不同顺序，两个题面均
  从 1.000 降到 0.000。

因此下降不是“更多证据降低质量”的证据，而是脚注映射顺序漂移的可重复产物。

## 已修复机制：跨节点脚注顺序漂移

Evidence ID 在一次运行内不会因 packer 过滤或重排而改变。deterministic Reporter
也不是罐装报告；它会从传入的 Evidence 动态生成正文、脚注和参考来源。

历史问题发生在两个节点之间：

1. packer 按质量分重排 Evidence，Reporter 按这个顺序分配脚注号。
2. Evaluator 开始前把 Evidence 恢复为规范排序。
3. Evaluator 没有复用 Reporter 的脚注映射，而是按新顺序重新构造映射。

脚注号由 Evidence 第一次出现的顺序决定。排序一变，同一脚注号就可能解析到另一条
仍然存在的 Evidence。引用解析率可以保持满分，但词面支持检查会对着错误 Evidence
执行，从而制造引用准确率下降。fixture 指标在这里测到的是内部顺序契约，而不是
packer 的证据选择质量。

本轮修复后，Reporter 把脚注到 Evidence ID 的映射随报告持久化，Evaluator 和
审计导出直接复用；默认、只重排、只删除、packer 排序和同映射五组对照在两个
题面上均为 1.000。历史伪信号已消除，但这只证明引用解析不再依赖顺序，不能把
fixture 中保留更多 Evidence 解释为真实研究质量提升。

## 对转正决策的后果

任何 `content_affecting` 开关，只要会改变 Evidence 集合、顺序、置信度或
报告上下文，都不能仅凭 fixture 质量数字转正。fixture replay 仍然有价值：它能
检出变化、证明确定性、检查安全边界，并暴露像脚注漂移这样的系统缺陷；但它不能
替代真实 LLM 模式下的内容质量验证。

这正是 context packer 与 injection guard 保持 dark 的方法论理由。packer
改变 Evidence 选择和顺序；injection guard 在命中时会改变置信度、Critic 路由，
并可能改变最终内容。两者都落在这一盲区。真实模式验证必须使用可比 manifest、
冻结输入、成对运行、引用闭合检查和人工或合格 judge 复核，不能把当前
deterministic 引用准确率当作代理结论。

## 盲区清单与识别规则

当前明确落入盲区的能力包括：

- Evidence 去重、截断、预算打包和重排；
- 多轮检索、分支预算再分配和跨期旧来源优先复核；
- injection guard 命中后的降置信度与路由变化；
- 检索结果 rerank、来源过滤、chunk 或摘录边界调整；
- 改变 ReportClaim 与 Evidence 对应关系的 Reporter 逻辑；
- 任何会改变引用编号、引用解析输入顺序或 citation scorer 支持文本的改动。

未来新增或修改能力时，按以下问题判断是否落入盲区：

1. 它是否会改变 Evidence 的成员、顺序、文本、ID、置信度或所属子问题？
2. 它是否会改变 Reporter 看见的上下文，或让报告与评分器读取不同的数据视图？
3. 指标是否由与被测能力共享的模板、排序或词面规则计算？
4. 在“只重排”“只删除”“保持报告与 Evidence 同一映射”对照中，质量数字是否
   会因内部表示变化而变化？

任一答案为“是”，characterization 结果只能表述为“行为发生或未发生变化”。
在完成真实模式的成对质量验证前，不得表述为“质量改善”“质量退化”或“具备
转正条件”。

## 015 确定性循环能证明与不能证明的内容

零 API fixture 验证可以证明：循环受轮次、调用预算和连续无进展边界约束；六项充分性
度量和同输入决策可重复；第二轮查询确实因缺口而变化；预算不会越过总量或单支上限；
跨期比较遵守四键和 scope，verify 仍保留独立检索；默认关闭时既有产物逐字不变。

它不能证明：当前充分性阈值对真实网页或 LLM 抽取有效；新增一轮提高结论覆盖而非放大
噪声；向弱分支拨预算优于其他策略；旧来源优先不会在真实检索排序中造成确认偏误；
`contradicts_prior` 的词面“解释变化”规则有足够召回；增加调用后的真实 token、延迟
和费用可接受。上述效果必须由 018 使用可比 manifest、冻结题面、成对真实模式运行、
引用闭合与人工/合格 judge 复核验证。在此之前三个 `content_affecting` 开关保持关闭。
